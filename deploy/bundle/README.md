# scheduler join bundle

Generated by the gateway (Gateway operations › Modules › scheduler › Add).

    docker compose up -d

`private/` holds credentials (the single-use enrolment token, the bundle's
TLS keys); `.env` and `config.yaml` hold generated passwords and the
event-bus password you gave. Keep them on this host only. The enrolment
token is valid for the lifetime chosen in the wizard; after the first start
the module renews its identity itself.

The scheduler joins the core's event bus (Valkey, TLS) as user `scheduler`:
the core's Valkey must accept that user from this host (streams
`platform:events:*`), so live task and execution status reaches the browser.

The scheduler runs tasks by calling the owning module. lcm is reached at its
core address; add every other executing module (ipam, notification, signing,
hr, asset, ...) to `discovery.static` in `config.yaml`, or its tasks fail
with "unknown service". On the core, each executing module lists
`scheduler: ["<this host>:9905"]` in its own `discovery.static` and allows
`spiffe://<trust domain>/svc/scheduler` to call
`/scheduler.v1.TaskExecutor/ExecuteTask` (rule `scheduler-execute`).
`policy.yaml` lets ipam, lcm, notification, signing, hr and asset register
task types; extend rule `modules-register` for any other executing module.
